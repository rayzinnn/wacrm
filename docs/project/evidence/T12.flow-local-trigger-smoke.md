# T12 — início de Flow no localhost

Verificado em 17/11/2026, somente no CRM/Supabase local:

- A rotina `scripts/evolution-events-local.mjs` agora chama o cron de eventos e, em seguida, o cron de Flow, a cada 10 segundos no localhost. O middleware permite a rota de Flow chegar à autenticação por bearer da própria rota; antes ela respondia 401.
- Antes de iniciar uma raiz nova, o executor confere se a definição está ativa e se o texto recebido combina com o gatilho de palavra-chave ou primeira mensagem. Fluxos manuais e gatilhos não correspondentes são ignorados sem criar run.
- Chamada real `--once` com fila vazia: eventos HTTP 200/0 reivindicados e Flow HTTP 200/0 reivindicados. O processo periódico foi reiniciado e mostrou ambos os ciclos HTTP 200.

A chamada real do cron retornou HTTP 200, 1 raiz reivindicada/1 concluída; o banco registrou run `completed` com 2 transições. A fixture inteira foi removida. Nenhuma mensagem foi enviada a WhatsApp ou outro destinatário.
- Uma segunda fixture descartável com palavra-chave sem correspondência retornou HTTP 200, 1 raiz ignorada e nenhum run criado. Também foi removida.
- Testes focados de gatilho, executor, rota e middleware passaram; `npx tsc --noEmit` passou antes do smoke. A integração de `send_message` e `collect_input` segue em andamento.
