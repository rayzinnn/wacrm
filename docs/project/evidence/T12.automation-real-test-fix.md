# T12 — automação testada no localhost

Em 17/11/2026, o usuário informou que a automação também não agia. Havia uma automação ativa `keyword_match` com um passo `create_deal` na posição 0, e duas tarefas Evolution pendentes. A rotina local chamava eventos e Flow, mas não chamava o cron de automação. Além disso, o executor de automação começava o percurso na posição 1 e ignorava o passo 0.

O middleware passou a entregar somente o GET exato de `/api/whatsapp/evolution/automation/cron` à rota que confere o bearer. O script local agora chama essa rota após eventos e Flow. O percurso começa na posição 0 e o teste unitário cobre a primeira ação nessa posição. Testes focados, TypeScript e lint passaram. Uma chamada manual ao cron retornou HTTP 200 e o runner atualizado retornou HTTP 200 para os três motores.

As duas tarefas antigas foram marcadas `done` antes da correção do cursor, com logs `success` de zero passos; nenhum negócio foi criado por elas. Não alterei seus registros para simular execução. A prova de criação de negócio requer uma nova mensagem de teste com o gatilho da automação.
