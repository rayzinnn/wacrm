# T12 — start dispatch RPC

## Implementação

Migration preparada em
`supabase/migrations/20261116201732_t12_start_evolution_event_dispatch.sql`.
`public.start_evolution_event_dispatch(uuid, uuid)` valida root processing,
lease/token vigentes, evento inbound Evolution aplicado, linhagem conexão/conta,
mensagem/conversa/contato, membership e definição/usuário da mesma conta.
Definição desativada ou contexto sem contato/conversa retorna `skipped` e limpa
a lease sem criar log/run.

Para automação, cria ou reusa o único `automation_logs` vinculado por
`evolution_dispatch_id`, inicialmente `partial`. Para flow, cria ou reutiliza o
run ativo da mesma definição e conta; o índice parcial atual resolve a corrida
de criação e um run vencedor de outra definição faz a candidata retornar
`skipped`. Para AI, a própria root continua sendo a execução; não há log/run
artificial. Start replay com lease renovada retorna o mesmo vínculo.

Conforme ajuste de contrato, a RPC não compara keywords, condições nem
elegibilidade de gatilho. Worker/engine deve decidir isso antes de chamar
`start`; pode concluir uma candidata `skipped` antes de start. A assinatura
atual não recebe decisão de elegibilidade e não há payload/flag SQL especulativo.

## Testes e estado local

- `supabase/tests/evolution-dispatch-start.sql`: fixtures sintéticas rollback-only; assinatura, `SECURITY INVOKER`, `search_path`, grants, token stale, tenant/definition, automação e flow idempotentes, lease renovada após crash, candidato inativo e AI sem linha artificial.
- `supabase/tests/evolution-dispatch-start-concurrency.sh`: duas sessões disputam start/replay do mesmo root e verificam um log vinculado. A limpeza foi ajustada para excluir o log antes da root, pois as FKs circulares usam `ON DELETE SET NULL`; a checagem final também procura logs órfãos da fixture.
- O SQL rollback-only foi executado localmente com a migration carregada dentro da mesma transação. Resultado: `CREATE FUNCTION`, verificações passaram e `ROLLBACK` encerrou a transação. Confirmei depois que a função não existe no catálogo e que `20261116201732` não foi registrado no histórico.
- A coordenação aplicou T11c e esta migration, nessa ordem, somente no banco local (`127.0.0.1:54322`). O SQL rollback-only passou novamente sobre a migration instalada; o teste de concorrência passou e confirmou um único log vinculado com limpeza verificada. Nenhuma mensagem real ou rede externa foi acessada.
