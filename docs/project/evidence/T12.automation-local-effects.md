# T12 — efeitos locais de automação (parcial)

## Entregue

Migration criada pela Supabase CLI 3.1.0:
`20261116203606_t12_apply_evolution_automation_effect.sql`, com
`public.apply_evolution_automation_effect(p_dispatch_id, p_dispatch_lease_token,
p_step_id, p_step_lease_token, p_operation, p_payload)`.

Este recorte habilita somente `add_tag`, `remove_tag` e
`update_contact_field` (colunas `name`/`email`/`company` ou
`custom:<custom_field_id>`). Exige root/step em `processing`, tokens e leases
vigentes, root de automação, vínculo do action key ao step da automação,
linhagem inbound Evolution/conta/contato/log e FK do alvo no tenant. Faz a
mutação local e chama `complete_evolution_dispatch_step(..., 'done', ...)` na
mesma transação; falha de fence reverte o efeito. Replay de step concluído não
autoriza novo efeito. A função é `SECURITY INVOKER`, search path fixo, execução
concedida somente a `service_role`.

O engine legado também dispara uma cadeia derivada `tag_added` quando uma tag
é inserida. Esta RPC altera somente `contact_tags`; o dispatch derivado
`tag_added` ainda não está implementado. Não ative worker usando esta RPC
isoladamente até existir um caminho idempotente para essa cadeia.

`create_deal`, `assign_conversation`, `wait` e `wait_for_reply` ficam para
recorte posterior; `close_conversation`, `send_webhook` e transporte continuam
fora. Operações não habilitadas falham fechadas sem efeito. Nenhuma alteração
na fila de waits foi incluída.
