# T11 — persistência local de novas mensagens no Evolution

Em 16/11/2026, alterei somente a configuração do serviço Evolution para que
novas mensagens recebidas sejam gravadas no banco local Evolution. Isso é
necessário para o endpoint key-only de mídia procurar a mensagem. O histórico
permanece desabilitado; capability de mídia continua vazia.

## Alteração e execução

- `infra/evolution/compose.yaml`: `DATABASE_SAVE_DATA_NEW_MESSAGE` mudou de
  `"false"` para `"true"`; `DATABASE_SAVE_DATA_HISTORIC` permaneceu `"false"`.
- `docker compose config --quiet`: exit 0 antes e depois da alteração.
- Contexto Docker: `colima-wacrm`.
- Serviço recriado com exit 0 usando:
  `docker compose up -d --no-deps --force-recreate --pull never evolution-api`.
- A operação recriou somente `evolution-api`; não fez pull, down, remoção ou
  recriação de dependências e não alterou volumes.

## Verificação sanitizada

Antes e depois, a API ficou `running/healthy`; GET local de saúde retornou
HTTP 200; a instância pareada permaneceu `connected`. Antes da recriação, os
volumes nomeados de instâncias/sessão, Postgres Evolution e Redis estavam
montados. Depois, os mesmos volumes estavam montados, sem alteração de nome ou
destino. Portanto, não foi observado risco concreto de perda da sessão e a
conexão foi preservada. Nenhum token, JID, identificador da instância ou dado
de mensagem foi registrado.

A coordenação confirmou previamente `count(*)=0` na tabela
`evolution_api."Message"`, sem ler conteúdo. Não consultei payload nem fiz
escrita SQL manual. Não enviei mensagem, não reexecutei os quatro eventos
anteriores e não alterei schema ou capability. As mensagens novas que o
Evolution receber passam a ser guardadas localmente na base Evolution; isso
amplia a retenção local de metadados e mensagens recebidas. Mensagens
históricas existentes não são importadas por esta configuração.

## Rollback

Para reverter o comportamento, alterar somente
`DATABASE_SAVE_DATA_NEW_MESSAGE` para `"false"`, validar com
`docker compose config --quiet` e recriar somente o serviço com o mesmo comando
acima. O rollback interrompe a persistência de novas mensagens; não apaga dados
já gravados. Não remover volumes nem executar `down -v`.

Nenhuma mensagem real foi enviada durante esta operação. A alteração não
reprocessou conteúdo antigo nem habilitou mídia.
