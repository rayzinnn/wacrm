# T12 — conclusão de dispatch root

## Implementação

A migration `20261116195927_t12_complete_evolution_dispatch` implementa somente
`public.complete_evolution_dispatch(p_dispatch_id uuid, p_lease_token uuid,
p_state text, p_result jsonb DEFAULT NULL, p_error_code text DEFAULT NULL)` com
retorno `public.evolution_event_dispatches`.

A função é `SECURITY INVOKER`, fixa `search_path = pg_catalog, public, pg_temp` e
concede `EXECUTE` apenas a `service_role`. Bloqueia o root, exige estado
`processing`, token igual e lease vigente. Valida a linhagem da conta pelo evento,
conexão Evolution, definição, usuário de auditoria e conversa/contato quando
presentes. Só aceita `done`, `skipped`, `failed` e `unknown`; recusa qualquer
conclusão terminal enquanto existir step `pending` ou `processing`.

O contrato não define um formato para `p_result`. A função exige que o parâmetro
seja `NULL`, persiste `result = NULL` e rejeita JSON não nulo; nenhum formato foi
inventado. Códigos de erro seguem o limite `[a-z0-9][a-z0-9_]{0,47}`; valores fora
dele são substituídos por `worker_error`. A conclusão limpa `lease_until` e
`lease_token`.

- Migration gerada pela CLI: `20261116195927_t12_complete_evolution_dispatch.sql`.
- `supabase migration up` confirmou o alvo local `127.0.0.1:54322`, mas a conexão
  expirou. A migration, grants e linha de histórico foram aplicados atomicamente
  via `psql` ao container `supabase_db_wacrm-local` no perfil `colima-wacrm`.
  Consulta local confirmou `20261116195927` registrado.
- `supabase/tests/evolution-dispatch-complete.sql`: exit code 0; concluiu com
  `ROLLBACK`. Verifica assinatura, segurança/grants, states terminais, rejeição de
  `p_result`, códigos de erro, tokens stale/expirado, isolamento de evento e
  definição por conta e bloqueio com steps pending/processing. Confirma que o
  root não muda quando a conclusão é bloqueada e que os estados finais limpam
  token/lease.
- `bash supabase/tests/evolution-dispatch-complete-concurrency.sh`: exit code 0.
  Duas sessões validaram os dois ordenamentos: step claim primeiro bloqueia
  conclusão; root completion primeiro bloqueia claim. O script verificou cleanup
  das fixtures sintéticas.
- `bash -n` e `git diff --check` passaram.

Os testes usam somente fixtures sintéticas locais, sem credenciais reais e sem
envio de mensagens. Nenhum worker, UI, engine ou rota foi alterado. Sem commit.
