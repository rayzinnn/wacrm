# T11 — Inbox composer para imagem e PDF

## Implementação

- Composer encaminha PNG/JPEG/PDF por POST autenticado para `/api/whatsapp/media/staging`, após validar MIME, extensão e limite de 16 MiB no cliente.
- A prévia raster usa o GET privado `/api/whatsapp/media/staging/{stageId}`; documento mantém nome e abre o GET autenticado para download. Nenhuma URL pública ou assinada é criada.
- Envio usa `/api/whatsapp/media/send` com `Idempotency-Key` gerada uma vez por estágio. A resposta inclui `message_id` UUID validado e troca o ID otimista nos estados aceito/incerto, evitando uma segunda bolha no realtime. `pending`, timeout e falha de rede não fazem retry nem afirmam entrega.
- A incerteza é somente UI no campo transitório da bolha; não há coluna/status persistido novo. Quando a linha realtime chega com o mesmo ID, a reconciliação dá precedência à linha/status do servidor e remove o rótulo transitório. Até esse evento, a tentativa continua como `sending`. Se a rede cair antes de retornar o ID, a reconciliação por conteúdo pode não casar um documento sem legenda (a bolha otimista usa o nome do arquivo); esse caso precisa de prova específica antes de habilitar mídia.
- O menu exibe Foto e Documento só se o tipo correspondente estiver na capability. `stageUpload` falha fechado sem capability; áudio/vídeo permanecem sem controles nem caminho de upload público neste composer.
- Integração permanece condicionada a `getEvolutionCapabilities().media`; o valor atual continua `[]`, portanto os controles não aparecem em localhost. Texto e fluxo legado permanecem intactos.
