# Evidência T13.a2b — bloquear reactions e broadcasts antigos

## Rotas bloqueadas

- `POST /api/whatsapp/react` autentica com `requireRole('agent')` e retorna HTTP 422, `Cache-Control: no-store` e `{ error: 'unsupported_capability', code: 'unsupported_capability', capability: 'reactions' }`.
- `POST /api/whatsapp/broadcast` e `POST /api/whatsapp/broadcast/[id]/resume` aplicam o mesmo gate e retornam `capability: 'broadcasts'`.
- As respostas 401/403 continuam vindo de `toErrorResponse` após `requireRole`; o handler acrescenta `Cache-Control: no-store`. `requireRole` é a primeira operação: corpo e params não são lidos.
- Os três módulos de rota agora importam somente `NextResponse` e os helpers `requireRole`/`toErrorResponse`. Saíram de cada rota Meta senders, decryption, engines, admin-client, rate limiting e acesso a tabelas. Não há leitura business, Graph/fetch, `after()`, update ou delete.

## RED/GREEN e validações

- RED antes de substituir as rotas: `npm test -- --maxWorkers=2 src/app/api/whatsapp/react/route.test.ts src/app/api/whatsapp/broadcast/route.test.ts 'src/app/api/whatsapp/broadcast/[id]/resume/route.test.ts'` — 9/9 falharam funcionalmente: retornos antigos 500, auth sem `no-store` e acesso aos params do resume.
- GREEN após a substituição: mesmo comando — 3 arquivos passaram, 9/9 testes. Casos confirmam 422 para usuário autorizado mesmo com body/params malformados, auth 401/403, `no-store`, nenhuma chamada a leitura business, rate limit, `after`, fetch/Graph e ausência de imports dos módulos Meta/engine/decrypt/admin observados.
- `npm run typecheck` — exit 0.
- ESLint direcionado aos seis arquivos de rota/teste — exit 0 sem avisos.
- Li o guia local Next 16.3.8 `node_modules/next/dist/docs/01-app/01-getting-started/15-route-handlers.md`: handlers usam `Request`/`Response`; o contexto de params é opcional. O resume não aceita nem consulta contexto/params.
- Não rodei a suíte completa; não alterei API v1, broadcast-core, send, health, media, UI, histórico ou dados. O teste não afirma que T13 inteiro foi concluído.

## Preservação e limites

As rotas só retornam o bloqueio após autenticação. Nenhuma gravação ou remoção de histórico foi executada. Os testes exercitam handlers isolados com auth stub e sentinelas locais; não fazem requisições de rede nem consultas reais.
