# Evidência T09.c2 — worker connection-only

## Contrato e fluxo

- `runEvolutionEventBatch()` chama o admin-client lazy e `claim_evolution_events` com `p_limit: 10` e `p_lease_seconds: 60`. Até 10 itens são processados com `Promise.all`; cada falha fica isolada.
- Somente `normalized_event.kind === 'connection'` é implementado. Outros tipos chamam `fail_evolution_event` com código constante e `p_retryable: false`.
- Lookup usa `whatsapp_connections` filtrada por `id=connection_id`; seleção exata: `id,provider,base_url,instance_name,token_encrypted`. Valida provider/origem, decripta o token e chama `getSession` uma vez. Não lê webhook secret/created_by, não grava estado por `saveSessionState` e não envia mensagem.
- Conclusão usa apenas `complete_evolution_connection_event(p_event_id,p_lease_token,p_state,p_checked_at)`, passando o token da claim atual e o `checkedAt` retornado pelo cliente. A migration concorrente implementa estado e evento done na mesma transação; este recorte não executou a RPC/banco real.
- Lookup de banco, rede, timeout e HTTP 429/5xx chamam `fail_evolution_event` com `p_retryable: true`. Origem/token/cripto inválidos, provider não suportado e 401/403 usam `false`. `40001`/`P0002` contam como `stale`, sem nova consulta nem nova conclusão. Outras falhas de complete deixam a lease recuperar e contam `retry` sem chamar fail.
- O erro de claim lançado ou retornado vira `EvolutionEventWorkerError` constante, código `event_worker_unavailable`, status 503 e sem causa. Falhas por evento retornam apenas contagens, não são logadas e não carregam mensagens brutas.
- `persistFailure` só conta `failed` quando o RPC devolve uma linha válida com `state='failed'`. `state='pending'`, resposta vazia/malformada sem erro ou falha na resposta contam `retry`, permitindo recuperação pela lease.

- `npm run typecheck` — exit 0.
- ESLint direcionado aos dois arquivos TypeScript — exit 0 sem avisos.
- Vite imprimiu o aviso preexistente de `configLoader: 'native'`/ESM em `vitest.config.ts` durante o teste. A suíte completa não foi executada.

## Limites

O contrato SQL e a migration `20261116051422_evolution_connection_worker.sql` foram apenas lidos; sua validação pertence a Âmbar.
