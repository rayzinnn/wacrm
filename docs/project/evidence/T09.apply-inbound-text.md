# T09.a — aplicação inbound textual

Data: 2026-11-16. Migration aplicada somente à stack Supabase local (`127.0.0.1:54322`); nenhum envio ou chamada externa ocorreu.

## Implementação

A RPC `public.apply_evolution_event(uuid, uuid)` recebe evento e token de lease. A aplicação de texto acontece na mesma transação que resolve contato/conversa, insere a mensagem, atualiza preview/unread por `bump_conversation_on_inbound`, cria raízes candidatas de automação/flow/AI e conclui o evento. O token e a validade do lease são conferidos sob lock do evento. Replay terminal e colisão do ID externo por conexão não repetem mensagem, unread nem raízes.

O recorte aceita somente `normalized_event.kind = message` com payload fechado de texto inbound (`fromMe=false`, `sentByApi=false`, `contentType=text`, `mediaRef=null`). Status e mídia ainda não observados são bloqueados com códigos estáticos; não criam mensagens nem raízes. `ai_configs.created_by IS NULL` omite apenas a raiz AI, sem substituir autoria pela conexão e sem impedir a mensagem inbound.

A função é `SECURITY INVOKER`, fixa `search_path = pg_catalog, public, pg_temp` e permite EXECUTE somente a `service_role`.
