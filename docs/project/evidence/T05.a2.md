# Evidência T05.a2 — configuração do webhook de conexão Evolution

**Data:** 2026-11-16
**Escopo:** método `configureWebhook` e testes no cliente isolado. Nenhuma chamada ao serviço Evolution, nenhuma configuração da instância principal, nenhum pareamento e nenhuma alteração no receptor, store, rotas, banco, catálogo ou ambiente.

## Contrato implementado

`configureWebhook(credentials, callbackUrl, webhookSecret, connectionId)` envia uma única requisição `POST /webhook/set/<instanceName-escapado>` com `apikey`, `accept: application/json`, `content-type: application/json`, `redirect: manual` e timeout de 15s. Não faz retry nem lê corpo da resposta.

O corpo contém somente:

```json
{
  "webhook": {
    "enabled": true,
    "url": "<EVOLUTION_WEBHOOK_BASE_URL>/api/whatsapp/evolution/webhook",
    "headers": {
      "x-wacrm-connection": "<connectionId>",
      "x-wacrm-webhook-secret": "<webhookSecret>"
    },
    "byEvents": false,
    "base64": false,
    "events": ["CONNECTION_UPDATE"]
  }
}
```

A callback esperada é derivada do `EVOLUTION_WEBHOOK_BASE_URL` do servidor. A base aceita apenas origem HTTP(S) sem credenciais, path, query ou fragmento; HTTPS é permitido e a exceção HTTP deste laboratório é exatamente `http://host.lima.internal:3000`. O `callbackUrl` recebido deve ser idêntico à origem canônica seguida do path fixo. Divergências falham antes de `fetch`. Esse path não recebe escolha do navegador.

Token, segredo, callback fornecido e corpo da resposta não são incluídos em mensagens de erro ou logs. 401/403 produz `unauthorized` sanitizado. Timeout, erro de rede, redirect ou HTTP 5xx de uma operação POST não repetida são marcados como ambíguos; em particular, timeout faz uma chamada só e `retryable=false`. Redirect é manualmente bloqueado, sem consumir seu corpo.

O evento habilitado é apenas `CONNECTION_UPDATE`; não são habilitados eventos de mensagens antes do normalizador. O método não gera nem rotaciona `webhookSecret`.
