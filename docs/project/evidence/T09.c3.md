# Evidência T09.c3 — cron autenticado e executor local

Data: 2026-11-16 (America/Sao_Paulo)

## Rota do cron

`GET /api/whatsapp/evolution/events/cron` roda em Node.js com `maxDuration=60`. Antes de chamar `runEvolutionEventBatch()`, valida `Authorization: Bearer …` contra `EVOLUTION_EVENTS_CRON_SECRET` usando `timingSafeEqual` somente após verificar comprimento igual e não vazio. Segredo ausente, env não configurado e bearer inválido recebem 401 no-store sem claim. A rota não lê body/query, sessão ou cookies. Sucesso expõe somente `claimed/done/retry/failed/stale`; qualquer erro retorna 503 com código fixo, sem log, causa ou texto bruto.

## Middleware

Somente o método GET no pathname exato `/api/whatsapp/evolution/events/cron` retorna `NextResponse.next()` antes de criar cliente Supabase ou chamar `getUser`. POST nesse caminho, subpaths e as rotas de status/connect seguem o guard existente. A query string não participa da decisão.

## Executor local

`scripts/evolution-events-local.mjs` usa apenas APIs Node built-in. Resolve o `.env.local` absoluto a partir do próprio arquivo e carrega-o por `process.loadEnvFile`; não imprime variáveis nem segredo. Faz GET somente para `http://127.0.0.1:3000/api/whatsapp/evolution/events/cron`, com timeout de 45 s. `--once` executa um ciclo e define exit code 1 em falha HTTP, rede, JSON ou configuração; sem a flag, aguarda cada ciclo antes de iniciar o próximo e programa início no intervalo de 60 s. Logs contêm apenas status e, para sucesso válido, as cinco contagens. O executor não foi iniciado nesta tarefa.
