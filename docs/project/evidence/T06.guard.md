## Testes

- `npm test -- src/lib/auth/redeem-invitation-migration.test.ts` — passou: 1 arquivo, 6 testes.
- `supabase/tests/evolution-invitation-guard.sql` — executado no Postgres local conectado em `127.0.0.1:54322` por driver temporário `psycopg`, dentro de `BEGIN`/`ROLLBACK`.
  - Uma conta pessoal sintética contendo somente uma linha de `whatsapp_connections` foi recusada com SQLSTATE `23505` e a mensagem esperada. Após a recusa, conta, owner/profile, conexão e convite não aceito foram verificados.
  - Uma conta pessoal sintética sem dados de domínio aceitou o convite; perfil e papel `viewer` foram movidos, a conta pessoal foi removida e o convite marcado como aceito.
  - Antes do teste, todas as outras tabelas consultadas pela guarda foram verificadas vazias para as duas contas-fonte; portanto nenhuma fixture dessas tabelas podia explicar a recusa.
  - Snapshots agregados de contas, perfis e conexões antes/depois foram iguais; nenhum usuário de fixture permaneceu após rollback. O teste criou somente UUIDs/identificadores sintéticos na transação, sem atualizar a conta principal configurada nem os dados da conta B.
- A tentativa inicial de executar o arquivo multi-statement por `supabase db query --file` foi rejeitada pelo modo de prepared statement antes da execução; foi usado driver PostgreSQL local com execução não preparada para executar o mesmo script transacional. A falha do CLI não alterou dados.
