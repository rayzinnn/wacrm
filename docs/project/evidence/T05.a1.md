# Evidência T05.a1 — cliente isolado de sessão Evolution

**Data:** 2026-11-16
**Escopo:** tipos C1, leitura de estado, início de conexão/QR e capacidades provisórias. Sem banco, rotas, UI, envio de mensagens ou chamadas ao serviço Evolution.

## Contratos implementados

- `EvolutionCredentials` contém `baseUrl`, `instanceId` (nome Evolution) e `token`. `SessionState` e `SessionSnapshot` preservam o contrato C1 original.
- `getSession(credentials)` consulta `connectionState`: `close` → `disconnected`, `connecting` → `connecting`, `open` → `connected`; demais respostas → `unknown`; `qr` é sempre null.
- `connectSession(credentials)` consulta `connect`. Resposta com QR retorna estado `connecting`, data URL PNG e expiração local em 20 segundos. Sem QR, observa `connectionState`; só retorna `connected` quando a resposta de estado contém `open`. Se não conseguir confirmar estado após iniciar conexão, o erro é marcado ambíguo e não repetível.
- `checkedAt` é criado no início da observação. Cada chamada HTTP tem timeout de 15 segundos, `redirect: manual`, header `apikey` e zero retry automático. Timeout de conexão é ambíguo; erros não carregam corpo, token nem causa original.
- `assertAllowedEvolutionOrigin(baseUrl)` é exportado para consumo pelo store em T06.b1. É sem I/O, rejeita URL com credenciais/path não raiz/query/hash e retorna origem canônica. HTTP é permitido somente para `http://127.0.0.1:8080`; toda origem aceita precisa constar em `EVOLUTION_ALLOWED_ORIGINS`. HTTPS canonicaliza host, porta padrão e slash raiz.
- QR exige prefixo exato `data:image/png;base64,`, base64 canônico, payload limitado a 5 MiB decodificados, assinatura PNG e IHDR com dimensões válidas. SVG, HTML, conteúdo inválido/truncado e payload excedente são rejeitados sem ecoar o valor.
- `getEvolutionCapabilities()` mantém `text=false`, `media=[]` e ações Meta-only (templates, broadcasts, reactions, interactive, typing) como booleanos false deste marco. Isso não declara C5 final concluído.
- Não existem stubs de envio neste recorte.

## Fixtures e testes

Os testes usam as fixtures sanitizadas existentes `infra/evolution/fixtures/instance-state.observed.json` e `auth-failure.observed.json`. O corpo de conexão usa o formato observado, mas a data URL vem exclusivamente do PNG sintético rotulado em `infra/evolution/fixtures/qr-synthetic-placeholder.png`; nenhum QR real é carregado.

RED: antes de implementar, o arquivo falhou ao resolver o cliente ausente. Depois das interfaces iniciais, os casos de canonicalização, resposta sem QR (`base64: null`), timeout durante parse e classificação retryable de 503 ambíguo ficaram vermelhos; foram corrigidos antes do GREEN. Os casos cobrem mapeamento de estados, QR sintético e expiração, autorização 401, timeout em fetch e JSON com uma chamada, origem anterior ao fetch, HTTP externo negado mesmo listado, canonicalização, URL da instância escapada, redirect manual, QR inválido e capacidades desativadas.

GREEN: `npm test -- src/lib/whatsapp/evolution/client.test.ts` — 32 testes passaram. `npm run typecheck` — passou. O runner emitiu aviso preexistente de compatibilidade do `configLoader` do Vitest; não afetou o resultado. Nenhuma suíte completa, banco, serviço externo ou instalação foi executada.

## Limites

Este cliente apenas observa estado/QR e inicia o fluxo de conexão. Nenhum pareamento foi realizado. Não prova conexão concluída nem implementa descarte no UI; `expiresAt` expressa a política local para consumidor futuro. Envio de texto/mídia, webhook, persistência e rotas ficam para recortes posteriores. C5 e T03 permanecem parciais.
