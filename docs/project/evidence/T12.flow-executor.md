# T12 — executor isolado de Flow Evolution

Data: 16/11/2026.

## Escopo implementado

`src/lib/flows/evolution-executor.ts` processa uma root `flow` já reivindicada,
confere engine/token, inicia ou reutiliza a `flow_run` com
`start_evolution_event_dispatch`, e percorre uma única run com limite de 40
transições por chamada. Cada transição usa uma chave de ação derivada de
run/seq/node, reivindica o step com `claim_evolution_dispatch_step` e grava o
checkpoint por `complete_evolution_flow_transition`. O fim do Flow conclui a
root por `complete_evolution_dispatch`; root/run/conta/contato são conferidos
antes de avançar.

Nós suportados neste recorte: `start`, `condition` (subjects `var`, `tag` e
campos de contato `name`, `email`, `phone`, `company`; operadores `equals`,
`contains`, `present`, `absent`) e `end`. Somente uma run `completed` conclui a
root como `done`; outros estados terminais concluem a root como `failed` com
código `flow_run_<status>`. Um checkpoint já concluído só é reconciliado quando
a sequência, status e próximo node da run correspondem ao retorno da RPC. Step
sob lease de outro worker não é reexecutado.

## Limites e lacunas

- `set_tag` não é executado: falta contrato que aplique a alteração da tag e o
  checkpoint Flow na mesma transação.
- `send_message` e prompt de `collect_input` não são executados. Embora o
  adapter de texto Evolution e a transição aceitem request IDs/attempts
  estáveis, falta contrato de claim Flow que vincule a tentativa reservada ao
  step antes da transição `message_sent`. O módulo não importa sender Meta nem
  adapter de envio e não faz POST.
- `send_media`, interativos, `handoff`, `http_fetch`, fallback e timeout também
  permanecem sem suporte neste executor.
- O módulo não reivindica roots, não cria rota/cron e não altera capability.
