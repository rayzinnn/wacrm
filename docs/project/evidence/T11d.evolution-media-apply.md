# T11d — aplicação SQL de mídia staged

Data: 2026-11-16

## Escopo implementado

Migration criada pela Supabase CLI 3.1.0 em `supabase/migrations/20261116204509_t11d_apply_evolution_staged_media.sql`. Ela usa `CREATE OR REPLACE FUNCTION public.apply_evolution_event(uuid, uuid)` e conserva o fluxo textual existente. A ramificação nova só aceita mensagem de imagem, documento, áudio ou vídeo já staged (`media_state='stored'`) com metadados completos, MIME compatível com `contentType`, hash/tamanho válidos e path determinístico derivado da conta da conexão Evolution e do UUID do evento.

A mensagem usa o `message_id` original, `content_type`, MIME em `media_type` e URL interna `/api/whatsapp/media/<event-uuid>`. A gravação é transacional com contato/conversa, unread e conclusão do evento. O token/lease é conferido antes de processar e novamente na conclusão; lease expirado não pode concluir a gravação. Replay terminal do mesmo evento retorna `duplicate` sem novo registro ou incremento de unread.

Mídia não cria dispatch roots de automação, flow ou IA. O ramo textual mantém os três inserts de roots existentes. Nenhum engine é executado por esta função.

## Caption e preview

T11b não persiste caption. A migration não lê nem tenta recuperar texto do webhook: `messages.content_text` permanece `NULL`. `bump_conversation_on_inbound` recebe `NULL`, mantendo preview neutro no banco. A UI atual pode interpretar preview nulo como `noMessagesYet`; fica registrada a pendência de UI/i18n para mostrar estado de mídia antes de habilitar qualquer capability. Não alterar UI neste recorte.

`getEvolutionCapabilities().media` permanece `[]`; o caminho SQL fica dormente até worker, rota e QA específicos autorizarem ativação.

## Limites

- Não houve upload/leitura de objeto Storage, blob, mensagem real, envio WhatsApp, chamada de instância, execução de engine ou ativação de capability.
- A migration ainda aguarda revisão da coordenação; não foi aplicada pelo Supabase CLI e não há commit.
- `mediaRef` exige `version` JSON number igual a 1 e `key.fromMe` JSON boolean false; validadores em blocos garantem que `jsonb_object_keys` só receba objetos.
- Não foi incluído tratamento de caption nem mudança de UI/i18n. A pendência deve ser resolvida antes da ativação.
