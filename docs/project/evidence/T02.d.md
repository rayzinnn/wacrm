# Evidência T02.d — signup com sessão imediata

Data: 2026-11-15. O relato reproduzido pelo coordenador no portal local indicou Supabase Auth com `enable_confirmations=false`: signup retornou sessão e criou usuário confirmado, perfil owner e conta, enquanto a UI exibia “Verifique seu e-mail”. Nenhuma conta real foi criada por esta tarefa.

## Diagnóstico

Em `src/app/(auth)/signup/page.tsx`, o retorno de `supabase.auth.signUp` era desestruturado apenas como `{ error }`. Depois de qualquer sucesso sem erro, o handler executava `setSuccess(true)`, descartando `data.session`; assim, sessão imediata e confirmação pendente recebiam a mesma tela.

O caminho de convite usa o token para calcular `next = /join/<token>` e `emailRedirectTo` aponta para `/auth/callback?next=...`. Ambos permanecem como estavam. A leitura do guia local `docs/auth-emails.md` e de `src/lib/auth/callback.ts` confirmou que o redirect de confirmação continua necessário quando não há sessão. O handler de login atual usa `window.location.href` porque uma navegação completa entrega os cookies de sessão ao middleware; a correção segue esse padrão para a sessão recém-criada.

## Alteração

O signup agora lê `data` e `error`; após sucesso, se `data.session` existir, navega com `window.location.href = next` e retorna. Se não existir sessão, continua para a tela existente de confirmação de e-mail. Convite, `emailRedirectTo`, conteúdo/i18n e comportamento de erros não foram alterados. Não foi introduzida regra de confirmação de produção.
