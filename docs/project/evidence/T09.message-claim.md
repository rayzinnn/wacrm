## Contrato

- Nova `public.claim_evolution_message_events(p_limit integer DEFAULT 10, p_lease_seconds integer DEFAULT 60) RETURNS SETOF public.evolution_events`.
- Reivindica exclusivamente `normalized_event.kind = 'message'`, respeita `pending` vencido e `processing` com lease expirada, usa `FOR UPDATE SKIP LOCKED`, incrementa `attempts` e emite token/lease novos.
- Limites são validados em `1..10` e `1..60`. Eventos elegíveis em `attempts >= 5` ficam `failed`, com lease/token limpos e erro `attempts_exhausted` apenas se ainda não havia código de erro.
- A função é `SECURITY INVOKER`, fixa `search_path` e concede `EXECUTE` somente a `service_role`. A implementação existente `claim_evolution_events` não foi alterada; `fail_evolution_event` segue sendo usado como RPC genérico de retry.
