# Evidência T07.a — configuração Evolution pela API

Data: 2026-11-16 (America/Sao_Paulo)

## Alteração

`GET /api/whatsapp/config` agora exige `requireRole('viewer')` e consulta somente `loadConnectionSummary` para a conta do contexto autenticado. Retorna DTO Evolution com `configured`, `provider`, `state`, `checkedAt` e `capabilities`; `baseUrl`/`instanceId` aparecem somente para owner/admin. Não consulta Evolution nem `whatsapp_config`, e não serializa ID interno, token, ciphertext ou QR.

`POST /api/whatsapp/config` exige `requireRole('admin')` antes de store ou rede, preserva o rate limit administrativo e aceita somente `baseUrl`, `instanceId` e `token`. Rejeita campos extras, inclusive `accountId`; deriva conta/ator do contexto; valida a origem com `assertAllowedEvolutionOrigin` antes de `getSession`; persiste conexão e snapshot de estado somente depois da validação do provedor. A resposta é DTO seguro.

Os erros são encaminhados ao `toEvolutionErrorResponse` compartilhado. Erro JSON de entrada inválida recebe 400 local genérico sem logging do `SyntaxError`. Respostas da rota usam `Cache-Control: no-store`. DELETE destrutivo foi removido; sem export DELETE, Next responde 405. A rota não mantém transporte Meta.
