# T06.c2 — cliente HTTP Evolution `sendText`

Implementado somente o cliente: `ProviderText`, `ProviderAcceptance` e `sendText`. O request usa `POST /message/sendText/:instance`, `apikey`, JSON `{number,text}`, converte apenas o JID individual `@s.whatsapp.net` para dígitos no limite HTTP e não transmite o `requestId`. Timeout de 15 s, redirect manual, sem retry/log; aceite exige 2xx, ID remoto não vazio, `fromMe=true` e `remoteJid` exatamente igual ao destinatário. O retorno contém somente `externalMessageId`.

A resposta 2xx ausente/inválida e falhas de transporte ficam ambíguas. Após revisão C2, HTTP 400 também é ambíguo: no código Evolution 2.3.7 fixado, `sendMessageWithTyping` pode falhar depois de `client.sendMessage` e o catch converte a falha da região em `BadRequestException` (`src/api/integrations/channel/whatsapp/whatsapp.baileys.service.ts:2289+ e 2558-2560`). Não se interpreta corpo de erro. Somente 401/403/404/422 são rejeições definitivas neste recorte; qualquer outro status não classificado fica ambíguo. Todas as falhas têm `retryable=false`.
