# Evidência T13.a2a — bloqueio backend de templates Meta

Data: 2026-11-16 (America/Sao_Paulo)

## Alteração

As mutações `POST /api/whatsapp/templates/submit`, `POST /api/whatsapp/templates/sync`, `PATCH /api/whatsapp/templates/[id]` e `DELETE /api/whatsapp/templates/[id]` agora exigem `requireRole('admin')` (owner/admin) e, após autorização, respondem `422` com `{ error: "Templates are not supported by this provider.", code: "unsupported_capability", capability: "templates" }`.

O bloqueio precede leitura de body e params, rate limit comercial, configuração, linhas de `message_templates`, decrypt, cliente Meta e fetch Graph. Os caminhos não inserem, editam ou apagam registros históricos. Não existem GETs nesses handlers para manter leitura de histórico; todos os quatro exports são operações mutáveis e estão bloqueados.

## Teste RED → GREEN

- RED contra os handlers Meta: 10 falhas relevantes demonstraram que submit/sync/PATCH/DELETE ainda executavam ou liam entradas antes do bloqueio; os casos de auth correspondentes mantiveram 401/403.
- GREEN final: `npm test -- src/app/api/whatsapp/templates/submit/route.test.ts src/app/api/whatsapp/templates/sync/route.test.ts 'src/app/api/whatsapp/templates/[id]/route.test.ts'` — exit 0, 3 arquivos e 16 testes passaram.
- `npm run typecheck` — exit 0 (`tsc --noEmit`).
- Os testes verificam sessão ausente, agent/viewer, admin autorizado, body válido com campos salvos/forjados, params, consultas comerciais, alterações locais e sentinelas Graph/cliente Meta. Nenhum payload é lido após a decisão de unsupported.
- O runner mostrou o aviso existente do Vite sobre `configLoader: 'native'` e sintaxe ESM em `vitest.config.ts`; as verificações passaram.

## Limites e preservação

Somente os três handlers e seus testes foram modificados. Validadores, categoria/status, templates históricos, broadcast/reaction, API v1, UI/catálogos, config Evolution, migrations e env foram preservados. Nenhum dado ou registro histórico foi alterado. Este recorte não conclui T13.
