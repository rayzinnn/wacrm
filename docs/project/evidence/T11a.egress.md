# T11a — egress guard for Evolution media

## Scope and decision

The media resolver is local-development-only until it has a transport that pins a validated DNS result to the actual socket, or an independently verifiable egress guard. It accepts only the configured literal origin `http://127.0.0.1:8080`. Although `EVOLUTION_ALLOWED_ORIGINS` can still contain HTTPS Evolution origins for other operations, `resolveMedia()` rejects those origins before calling `fetch()`.

This avoids a DNS pre-check followed by an unchecked connection lookup. OWASP notes that a domain allowlist alone does not prevent DNS rebinding and requires the HTTP connection to use the validated address. External media retrieval therefore remains unavailable until that connection binding or an equivalent egress policy is implemented.

## Changes

- `src/lib/whatsapp/evolution/media.ts`: added the local-development origin guard after credential/origin validation and before URL creation, timeout setup, or fetch. Existing media key, response size, MIME, signature, filename, redirect, and error handling remain intact.
- `src/lib/whatsapp/evolution/media.test.ts`: added a regression showing an otherwise allowlisted external HTTPS hostname returns `origin_not_allowed` with zero fetch calls. Existing localhost tests continue to use a mocked fetch.
- No schema, worker, UI, capability, Next route, or dependency files changed. No DNS lookup, live fetch, or real WhatsApp call was performed.
