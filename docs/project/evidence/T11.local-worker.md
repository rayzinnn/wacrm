# T11 — inbound Evolution media worker integration

## Behavior

- `message-worker.ts` keeps the existing text path and adds a branch for image, document, audio, and video events only when their kind is in `getEvolutionCapabilities().media`. The configured capability remains `[]`, so real media events still fail closed as `unsupported_media_kind` before credential lookup, resolver, Storage, or apply RPC.
- For enabled media with `media_state='pending'`, the worker reads Evolution credentials only from the event's `whatsapp_connections` row, decrypts the server-side token, calls `resolveMedia`, stages through `stageEvolutionInboundMedia`, then calls `apply_evolution_event` with the current lease.
- Before staging, the worker rejects a resolved file whose media kind differs from the normalized event, preventing an orphaned upload for mismatched provider content.
- For enabled media already marked `media_state='stored'`, the worker calls `apply_evolution_event` directly. It does not resolve credentials, download again, or stage again; the SQL RPC validates the stored path, metadata, tenant, and lease.
- Stale stage results stop without `apply_evolution_event` or `fail_evolution_event`. Permanent media/connection/stage failures and transient provider/Storage/database failures call `fail_evolution_event` with a stable code and retryability flag; raw errors, media bytes, refs, and credentials are not passed to that RPC or logged.
- The replay path covers a crash after stage followed by a transient apply failure: `fail_evolution_event` makes the event retryable while `media_state='stored'` remains; the next claim applies stored media directly, with no second download or stage.

## Contract and limits

This integration relies on `supabase/migrations/20261116204509_t11d_apply_evolution_staged_media.sql`, whose `apply_evolution_event` transaction accepts only staged media with validated metadata and creates the message plus marks the event done atomically. SQL, routes, UI, and capability files were not edited in this recut.

`resolveMedia` currently permits only the configured literal loopback origin for downloads. External Evolution origins remain blocked until a pinned-destination transport or equivalent egress guard exists. No media kind was enabled.
