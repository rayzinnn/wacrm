# T12 — reserva local para envio interativo

Em 17/11/2026, a RPC `reserve_evolution_interactive_send` foi aplicada somente no Supabase local. Ela recebe o payload de botões ou lista, prende o ID da etapa ao hash do conteúdo completo e cria uma tentativa e uma mensagem `interactive` na mesma transação. Repetir a mesma solicitação retorna a tentativa existente sem autorizar outro envio. A conclusão reutiliza `complete_evolution_send`, que registra aceitação, rejeição ou resultado incerto.

O teste SQL de rollback confirmou reserva, replay, conflito de hash, isolamento entre contas, conclusão aceita e mensagem persistida. Os módulos de transporte e adapter passaram em testes isolados: uma resposta HTTP ambígua não dispara segundo POST. Os dados usados nos testes foram temporários; nenhuma rota de envio real foi chamada.

Essa reserva ainda não está conectada ao executor do Flow. Botões e listas continuam bloqueados na ativação até a entrada da resposta e o avanço único por escolha estarem integrados.
