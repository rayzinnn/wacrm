# T10 UI — Inbox de texto e reconciliação

Data: 2026-11-16. Recorte local limitado aos componentes Inbox, helper de operação e teste próprio.

## Comportamento

- A ação de texto cria um `requestId` por envio e grava operação/conteúdo em `sessionStorage` antes do POST. O POST envia a chave no header `Idempotency-Key` e ocorre uma única vez.
- Timeout, erro de rede, resposta ambígua ou sucesso sem ID preservam o registro como `unknown` e consultam `GET /api/whatsapp/operations/{requestId}`. Estado `pending`/`unknown` permanece recuperável após reload e reusa a mesma chave. O botão de atualização consulta somente GET; nunca repete POST.
- Ao montar uma conversa, operações pendentes do mesmo thread restauram a bolha otimista e consultam a operação. `accepted` atualiza a bolha com o ID de mensagem persistido; `rejected` marca falha e remove a operação local. A deduplicação realtime/fetch existente permanece ativa.
- A mensagem pendente/indeterminada tem status acessível (`role=status`, `aria-live=polite`) e informa que não haverá reenvio automático. O botão de consulta descreve esse status. O rascunho do composer só é limpo quando a operação foi armazenada e enfileirada.
- Os estados, o erro de armazenamento e o aviso de capability têm chaves em `messages/{en,pt,es,ko}.json`. O aviso usa linguagem de produto (“envio de texto indisponível no momento”), sem expor etapas internas.
- `replyToId` ainda é contexto não suportado pelo core. O handler bloqueia a ação antes de gravar operação ou bolha otimista, mostra aviso localizado e retorna `false`; assim o composer mantém o texto e a citação. Nenhum POST é iniciado.
- A restauração observa o ID primitivo da conversa e só atualiza `pendingTextOperations` quando a lista/estado mudou. Os callbacks recebidos de Inbox são estáveis (`useCallback` no pai), evitando reexecução por identidade de objeto da conversa e evitando `setState` redundante.
- `getEvolutionCapabilities().text` continua `false`: o botão fica desabilitado com explicação acessível e o handler também recusa o envio. Nenhuma capability, rota ou SQL foi alterada; mídia/template/interativo continuam fora do caminho de envio textual.
