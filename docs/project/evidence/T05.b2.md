# T05.b2 — inbound textual callback normalization

## Result

The webhook normalizer now recognizes only the observed Evolution `messages.upsert` shape for inbound plain text. It emits a minimal `message` event when `messageType` is `conversation`, `key.fromMe` is `false`, `key.remoteJid` is a direct international-number JID matching `8–15 digits@s.whatsapp.net`, and `message.conversation` is nonempty. `messageTimestamp` must be a nonnegative safe integer in Unix seconds and is converted to ISO UTC for `occurredAt`.

The stable event key is `message:sha256:` plus SHA-256 of `JSON.stringify([externalMessageId])`; message text, timestamp, and receiver time do not affect identity. The output fixes `fromMe:false`, `sentByApi:false`, `contentType:'text'`, and `mediaRef:null`. Text is preserved without trimming. The `instance` envelope field must be a nonempty string; provider `date_time` is not used as the inbound timestamp authority.

Malformed recognized message shapes raise the fixed `NormalizationError` (`Invalid webhook event`), without payload details. Valid but unsupported variants return no events: self messages, group/broadcast/LID or otherwise unsupported JIDs, non-conversation message types (including media and extended text), and event names outside the supported connection and inbound-text cases. The parser does not infer that an outbound message was sent by this API.

## Queue and activation boundary

Queue persistence explicitly projects the permitted fields for each normalized event variant; it does not spread or persist raw callback data. Deduplication remains on `(connection_id, event_key)` with duplicate rows ignored. Tests cover the message projection, removal of extra/context fields, and replay deduplication.

The public webhook route still authenticates first, then enqueues only `connection` events. A normalized message-only request is acknowledged as ignored and never enters the current connection-only worker. Mixed batches enqueue only connection events. This change does not enable message webhook subscriptions, message processing, text-send capability, or any transport behavior.

## Evidence and limits

Its peer and message ID are placeholders; the test substitutes only a synthetic PN JID and does not call the normalizer to generate its expected value. Other test payloads and text strings are synthetic. The fixture's observed metadata records an inbound callback correlated by the verified JID lookup; it was not classified as a reply to the requested send marker. The callback's content is redacted.
