# T11c — verificação local do Storage API

## Resultado

Teste concluído no Supabase local contra `evolution-media`, sem alterar schema ou capability:

| Operação | Resultado |
| --- | --- |
| Upload `text/plain` pequeno via Storage API com `service_role` | sucesso |
| GET com chave anon, sem sessão | negado, HTTP 400 |
| GET com sessão de usuário autenticado sintético | negado, HTTP 400 |
| Download via Storage API com `service_role` | sucesso; bytes iguais ao sentinela sintético, comparação em memória |
| Remoção do objeto via Storage API com `service_role` | sucesso |
| Verificação Storage posterior | objeto ausente |
| Conta sintética | apagada antes do usuário; zero contas com o owner sintético |
| Perfil sintético | zero perfis para o usuário sintético |
| Usuário Auth sintético | apagado; lookup por ID retornou 404 |

Todos os dados e bytes do objeto foram sintéticos. O payload ficou em memória e não foi impresso. Nenhum identificador, chave ou token foi registrado nesta evidência.

## Método

- Carregado o ambiente local com `source /Users/raymozer/.local/share/wacrm-infra-a/env.sh` e conferido o stack usando `docker --context colima-wacrm ps --format '{{.Names}} {{.Status}}'`. O contexto exibiu nove containers WACRM/Supabase locais; o teste de API confirmou o caminho funcional.
- Um script Node de uso único leu `.env.local` em memória com `dotenv` e `@supabase/supabase-js`. Antes de qualquer chamada, validou que `NEXT_PUBLIC_SUPABASE_URL` apontava a `localhost`, `127.0.0.1` ou `::1`. A saída do script continha apenas estados booleanos e códigos HTTP.
- Criado um usuário Auth com email aleatório no domínio reservado `.invalid`; o trigger local criou a conta/perfil associados. A sessão foi obtida com credenciais aleatórias geradas somente em memória.
- Criado path aleatório sob `account-<UUID sintético>/evolution/…` e confirmado que estava ausente antes do upload. O objeto continha somente um pequeno sentinela UTF-8 `text/plain`.
- Executado GET anon com `apikey` anon e sem Authorization; depois GET com `apikey` anon e bearer da sessão sintética. Ambos retornaram HTTP 400 e nenhum corpo foi lido ou exibido.
- `service_role` baixou o objeto pelo Storage API e o conteúdo foi comparado em memória ao buffer sintético. Nenhum byte foi escrito em stdout/log.
- Em `finally`, removido primeiro o objeto pelo Storage API; apagada em seguida apenas a conta cujo owner era o UUID sintético; por último apagado o usuário Auth sintético. Após a limpeza, Storage `exists` indicou ausente, contagens das linhas sintéticas de conta/perfil foram zero e Auth lookup retornou 404.

## Limites

- A negação foi verificada para GET direto do objeto privado no Storage API local; não foram testadas listagem, operações de escrita por usuários, rotas autenticadas do WACRM nem acesso cruzado entre duas contas autenticadas.
- Nenhuma mensagem, mídia pessoal, QR ou instância WhatsApp foi consultada. Nenhum envio WhatsApp foi feito.
- A migration T11c já estava aplicada no banco local antes deste teste; não rodei `migration up`, não alterei schema/capability e não fiz commit.
