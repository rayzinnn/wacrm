# T12 — pergunta e resposta textual no Flow Evolution local

Em 17/11/2026, o executor local passou a tratar `collect_input` como uma pergunta de texto. O prompt usa a reserva de envio Evolution e só vira checkpoint `message_sent` após aceite conhecido. O Flow permanece ativo no mesmo nó enquanto aguarda outra mensagem. A root do evento que iniciou a pergunta termina, sem interpretar aquele próprio evento como resposta.

Quando chega outro texto do mesmo contato, o worker pode vincular a nova root ao run ativo. A RPC `complete_evolution_flow_collect_input_reply` exige root e step com leases válidos, evento inbound aplicado, conta/contato/run coerentes, prompt enviado e `transition_seq` atual. Ela guarda o texto aparado apenas em `flow_runs.vars[var_key]`, registra `reply_received` com payload vazio e move o cursor ao próximo nó na mesma transação. Repetir o mesmo evento não avança novamente. Mensagens de mídia, próprias ou enviadas pela API não entram no gatilho de resposta.

Também corrigi a elegibilidade de `first_inbound_message`: a primeira mensagem recebida é identificada pelo histórico persistido da conversa, em vez de comparar o horário do provedor com `messages.created_at` do servidor. Uma nova root não assume um run já em outra ação; se houver um run ativo, ela só entra como resposta de um `collect_input` que tenha prompt registrado.

Verificações: migration aplicada apenas no Supabase local; teste SQL rollback-only passou em captura, replay, sequência antiga, conta cruzada, prompt ausente, grants e índice de unicidade. O teste do executor cobre pergunta, resposta seguinte, ausência de reenvio e proteção contra usar o evento inicial como resposta. Suíte integral: 200 arquivos e 2.167 testes; typecheck, ESLint focado e build Next passaram.

Limite: não houve envio automático real pelo WhatsApp nesta rodada. O banco local tem zero fluxos cadastrados/ativos, então o Flow específico do usuário ainda não foi reproduzido. Nós interativos (`send_buttons`, `send_list`) e outras ações permanecem indisponíveis no executor Evolution.
