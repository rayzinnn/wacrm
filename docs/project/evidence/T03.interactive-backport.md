# T03 — Backport local de mensagens interativas Evolution 2.3.7

Data: 2026-11-17 (America/Sao_Paulo)

## Implementação local

- Base imutável: `evoapicloud/evolution-api:v2.3.7@sha256:0e5d84f45b390e1d659500c9a98bfa2a53be28a341fbc0864966b77485f2a0c5`, fonte `2.3.7` commit `cd800f2976e1e5b682fbf86a01ee4d85ae61f370`.
- O build em `infra/evolution/build/Dockerfile` continua aplicando a remoção do log bruto `messages.upsert` e agora executa `patch-interactive-messages.mjs` nos bundles Baileys `.js` e `.mjs`.
- O script exige uma ocorrência exata do builder de botão comum com `viewOnceMessage`, uma condição de dispatch, uma chamada relay, um builder de lista legacy e duas clonagens JSON protobuf. Desvio de versão/compilação aborta o build. Cada arquivo só é gravado após os dois bundles passarem pelas asserções.
- Botões comuns (reply/CTA): remove apenas os dois invólucros `viewOnceMessage.message`; mantém `interactiveMessage`, payload, envio pelo `sendMessageWithTyping`, `messageId` entregue ao `relayMessage` e chave/ID de resposta construída a partir do ID retornado. Acrescenta `<biz><interactive type="native_flow" v="1"><native_flow v="9" name="mixed"/></interactive></biz>` por `additionalNodes`.
- PIX permanece no ramo separado com seu payload/wrapper original; esta correção não habilita nem afirma corrigir PIX em clientes móveis.
- Listas continuam em `listMessage` legacy, passam a `SINGLE_SELECT` (enum 1) e recebem `<biz><list type="product_list" v="2"/></biz>` por `additionalNodes`.
- As duas clonagens `JSON.parse(JSON.stringify(message))` do hook são removidas, mantendo a mutação `PRODUCT_LIST` → `SINGLE_SELECT` no objeto protobuf original para preservar `Long`.
- Alterações no repositório: `infra/evolution/build/Dockerfile`, `infra/evolution/build/patch-interactive-messages.mjs` e esta evidência. Nenhum arquivo do clone upstream, Compose, serviço WACRM ou serviço em execução foi alterado.

## Limites

O ramo PIX segue fora desta correção.
