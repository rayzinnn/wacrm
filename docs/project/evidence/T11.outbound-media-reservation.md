# T11 — reserva durável para envio outbound de mídia

Data: 17/11/2026 (America/Sao_Paulo).

`media-send.ts` agora pode ser chamado pelo novo `media-send-adapter.ts`, que faz validação completa do arquivo antes da reserva, calcula um hash determinístico incluindo destinatário, tipo, MIME, nome, legenda e SHA-256 dos bytes, reserva uma mensagem/tentativa antes do POST e só chama o transporte quando a RPC retorna `should_send=true` e `outcome='pending'`. A chave estável `requestId` fica no banco e não é enviada à Evolution. A conclusão usa a RPC existente `complete_evolution_send`.

## Interface SQL confirmada

- `reserve_evolution_send(connection_id, request_id, request_hash, conversation_id, sender_type, sender_id, message)` é a reserva de texto e rejeita explicitamente qualquer `content_type` diferente de `text`.
- `reserve_evolution_interactive_send(...)` cria reserva/mensagem interativa e não é genérica para mídia.
- As duas usam `evolution_send_attempts` com unicidade `(account_id, request_id)`, retornam `attempt_id`, `message_row_id`, `outcome`, `should_send` e usam `pending`, `accepted`, `rejected`, `unknown`. Em replay, retornam a tentativa existente e `should_send=false`; `complete_evolution_send` aceita o resultado `unknown`. A reserva antiga também converte `pending` expirado em `unknown`, sem reautorizar envio.
- Foi necessária uma RPC estreita `reserve_evolution_media_send` em migration aditiva, pois nenhuma interface existente aceita `image`/`document`. A nova função permite somente PNG/JPEG/PDF, grava uma mensagem local `sending`, vincula tentativa/conexão/conversa/autor à mesma conta e aplica a mesma unicidade de solicitação por conta. Sua permissão de execução é apenas `service_role`.

## Evidência e limites

- `media-send-adapter.test.ts` cobre ordem reserva→transporte→conclusão, replay em todos os estados, timeout `unknown` com uma chamada única, falha da reserva antes da rede e rejeição de arquivo inválido antes da reserva.
- `media-send.test.ts` mantém cobertura do POST sintético. Não houve chamada real à Evolution/WhatsApp, acesso a dados pessoais, Storage, rota, UI ou capability.
- Migration: `20261117190000_t11_reserve_evolution_media_send.sql`. Teste rollback-only preparado em `supabase/tests/evolution-media-send-reservation.sql`, para replay, hash conflitante, isolamento entre contas, recusa cross-account e tipos não permitidos.
- Testes TypeScript e ESLint focados passaram; `npm run typecheck` passou. Na tarefa do agente, o teste SQL não foi executado porque `supabase`, `psql` e `pg_isready` não estavam disponíveis em seu terminal.
- O coordenador revisou a migration e a função existente `complete_evolution_send`, aplicou a migration **somente** no Supabase local via `psql` dentro do container já existente e executou o teste SQL rollback-only: `BEGIN`, `DO`, `ROLLBACK`, sem erro. Registrou a versão `20261117190000` como aplicada no histórico local com `supabase migration repair`; a listagem confirmou a versão. Nenhum container foi recriado e nenhum banco remoto foi alterado.
- O adaptador aceita a mídia em bytes já fornecida pelo chamador; upload privado e obtenção dos bytes, autorização de rota, UI e capability continuam fora deste recorte. Até essas etapas, este módulo não deve ser ligado a uma rota ou ativado.
